# Prepare a 1:1

1. Ask for the attendee, timeframe, and any expected meeting format if they are not already supplied. Use the last 7 days by default.
2. Read relevant recent material from `00-INBOX`, `01-CAPTURES`, `02-CONNECTIONS`, `1on1s`, and person or topic files in `05-CLAUDE/context/`. Incorporate available read-only calendar context for attendees, timing, and open commitments; do not invent calendar facts or persist raw event details.
3. Use GitHub activity when it is relevant and authorized: identify recent PRs, open work, issues, comments, and commits for the user and relevant repositories.
4. Produce three concise sections:
   - **What I Tried:** Shipped, built, investigated, or advanced work with concrete evidence.
   - **What Didn't Work:** Failures, blockers, surprises, and likely causes.
   - **What I Learned:** Insights and changes in understanding, connected to a broader goal when useful.
5. Include links or file references for important claims and print the draft for review before saving or sending it.

Keep the update direct, specific, and honest. Do not invent activity or claim outcomes without evidence.
